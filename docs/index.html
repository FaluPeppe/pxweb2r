Pxweb2r

Hämta statistik från en PxWeb API v2 med paketet pxweb2r

Författare

Peter Möller

Utgiven

5 november 2026

1 Inledning

Det här dokumentet är en enkel och praktisk introduktion till hur man hämtar data från SCB:s PxWebAPI version 2, med R-paketet pxweb2r. Syftet är att snabbt kunna komma igång med datahämtning, förstå de vanligaste parametrarna och känna till de hjälpfunktioner som underlättar arbetet.

Paketet gör API-anropen mer lättanvända genom att bland annat:

  • hämta metadata och variabelvärden (inklusive kodlistor/aggregeringar),
  • skapa query-listor,
  • tillåta både koder och klartext i urval,
  • möjliggöra att flera tabeller hämtas i samma anrop och läggs ihop till ett dataset,
  • hantera senaste tidsperiod med "9999",
  • hantera wildcard-uttryck som "2083*",
  • hantera DeSO-/RegSO-versioner,
  • kontrollera om en tabell uppdaterats sedan ett visst datum,
  • och returnera data i ett analysvänligt format (en tibble).
NoteraEngelska funktions- och parameternamn

pxweb2r har engelska funktions- och parameternamn (pxweb2_get_data(), query, table osv.). Själva innehållet i query-listorna (Region, Kon, ContentsCode, Tid …) är dock alltid på det språk tabellens metadata råkar använda, oftast svenska för SCB:s tabeller.

2 TL;DR

Snabbstart för dig som vill komma igång direkt:

library(pxweb2r)

# hämta tabell-id, antingen direkt från SCB:s öppna statistikdatabas eller
# genom att söka efter tabeller med funktionen pxweb2_search_tables()
pxweb2_search_tables("hushållstyp per region")

# välj en av tabellerna, tex TAB6568 - skapa ett färdigt pxweb2_get_data()-anrop
# för just den tabellen med pxweb2_data_script_template()
pxweb2_data_script_template("TAB6568")

# anropet läggs automatiskt i urklippshanteraren och kan klistras in i ett
# R-skript. Med Ctrl + V direkt efter att du kört pxweb2_data_script_template("TAB6568")
# får du således anropet nedan

# Antal hushåll per region efter hushållstyp. År 2011-2025
dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region       = "2083*",
    Hushallstyp  = "*",
    ContentsCode = "*",
    Tid          = "*"
  )
)

# Nu har du data i dataset_df och kan börja bearbeta datasetet!

Detta hämtar data från tabellen TAB6568, väljer alla regionkoder som börjar med 2083, alla hushållstyper, allt tabellinnehåll och den senaste tidsperioden.

Vanliga specialvärden:

Uttryck Betydelse
"*" Alla värden för variabeln
"9999" Senaste tidsvärdet för tidsvariabeln
"2083*" Alla koder som börjar med 2083
"202?M12" Matchar ett tecken med ?, till exempel december för 2020-talet
c("2083A*", "2083B*", "2083C*") Flera wildcard-uttryck i samma variabel (i detta fall för att ta med alla DeSO i Hedemora kommun)

3 Utforska tabeller och metadata

Innan man hämtar data är det ofta bra att förstå tabellens struktur: vilka variabler som finns, vilka värden de kan anta och vilken tidsperiod tabellen täcker.

3.1 Söka tabeller

Funktionen pxweb2_search_tables() kan användas för att hitta tabeller.

tabeller_df <- pxweb2_search_tables("hushåll")

Exempel med fler argument:

tabeller_df <- pxweb2_search_tables(
  query               = "befolkning",
  lang                = "sv",
  pageSize            = 200,
  includeDiscontinued = FALSE
)

3.2 Hämta metadata

När du vet tabell-id kan du hämta metadata:

meta <- pxweb2_get_metadata("TAB6568")

Metadataobjektet används av flera andra funktioner och kan skickas vidare för att slippa göra API-anrop flera gånger.

Vill du bara kontrollera att en tabell faktiskt existerar, utan att göra något med resultatet:

pxweb2_table_exists("TAB6568")   # TRUE/FALSE

3.3 Lista variabler

Om du vill lista en tabells variabler så kan du använda pxweb2_get_variables(). Den tar antingen ett tabell-id (t.ex. "TAB6568") eller ett metadataobjekt som argument:

pxweb2_get_variables(meta)

Använder du ett metadataobjekt behöver inte ett nytt API-anrop göras, men det går att använda ett tabell-id direkt (om man inte redan gjort ett metadataobjekt):

pxweb2_get_variables("TAB6568")

Om du vill spara resultatet i en data frame:

variabler_df <- pxweb2_get_variables(meta)

Typiska kolumner i resultatet är:

Kolumn Beskrivning
code Variabelns kod i API:t
label Variabelns klartextnamn
size Antal värden
elimination Om variabeln kan utelämnas
role Till exempel time, geo, contents eller other
show Hur värden visas i metadata/API

3.4 Lista värden för variabler

Om du vill se tabellens värden för samtliga variabler:

varden <- pxweb2_get_values(meta)

Du kan också skicka med en eller flera variabler i parametern variables. Du kan använda både kod och klartext för variabeln (code eller label). Från tabellen vi hämtade metadataobjektet meta ovan kan vi alltså använda region eller Region (blir samma sak då parametern är skiftlägesokänslig, dvs. stora och små bokstäver spelar ingen roll), eller såväl ContentsCode som tabellinnehåll:

regioner <- pxweb2_get_values(meta, variables = "Region")

Det är särskilt användbart för att se vilka koder som finns:

regioner |>
  dplyr::filter(stringr::str_starts(code, "2083")) |>
  dplyr::select(code, label)
TipsStora variabler och aggregeringar: include_aggregations

Vissa variabler (framför allt Region) har färdiga kodlistor och aggregeringar i PxWeb — t.ex. “alla kommuner i ett län” eller “lokala arbetsmarknadsregioner”. pxweb2_get_values() har parametern include_aggregations ("auto" som standard, annars "all"/"none"/"codelists", eller en namngiven vektor per variabel) för att styra om och hur mycket av det som hämtas. Vill du hämta en enskild kodlista direkt, utan att gå via pxweb2_get_values(), använd pxweb2_get_codelist(); pxweb2_list_codelists(meta) visar vilka kodlist-id:n en tabell faktiskt erbjuder.

4 Hämta data med pxweb2_get_data

Den viktigaste funktionen är pxweb2_get_data(). Den hämtar data från en tabell och returnerar en tibble.

4.1 Grundexempel

dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region       = "2083",
    Hushallstyp  = "*",
    ContentsCode = "*",
    Tid          = "*"
  )
)

4.2 Använd metadataobjekt istället för tabell-id

Om metadata redan är hämtad kan den skickas direkt:

meta <- pxweb2_get_metadata("TAB6568")

dataset_df <- pxweb2_get_data(
  table = meta,
  query = list(
    Region = "2083",
    Tid    = "9999"
  )
)

Det kan vara praktiskt när man ska göra flera uttag från samma tabell.

5 Hämta data från en eller flera SCB-tabeller

5.1 Hämta data från en tabell

Det enklaste fallet är att hämta data från en enda tabell. Tabellen anges med argumentet table, och urvalet anges i query.

dataset_df <- pxweb2_get_data(
  table = "TAB6766",
  query = list(
    Region       = "2021",
    Kon          = "*",
    ContentsCode = "*",
    Tid          = "*"
  )
)

I query anges vilka värden som ska hämtas för respektive variabel. Tecknet "*" betyder att alla värden för variabeln hämtas (API:ts eget wildcard, se Vanliga urval i query).

5.2 Hämta den senaste tidsperioden

Om "9999" används för tidsvariabeln hämtas den senaste tillgängliga tidsperioden i tabellen. Önskar du ett annat alias än "9999", eller att funktionen ska strunta i senaste-period-hanteringen helt, styr latest_period_code (NULL stänger av den).

dataset_df <- pxweb2_get_data(
  table = "TAB6766",
  query = list(
    Region       = "2021",
    Kon          = "*",
    ContentsCode = "*",
    Tid          = "9999"
  )
)

Detta är praktiskt när man vill slippa ändra årtal manuellt när SCB uppdaterar en tabell.

5.3 Hämta och lägga ihop flera tabeller

I vissa fall är samma statistik uppdelad på flera SCB-tabeller, till exempel eftersom äldre och nyare årgångar ligger i olika tabeller. Då kan flera tabell-id:n skickas in som en vektor i table.

dataset_df <- pxweb2_get_data(
  table = c("TAB3266", "TAB3267", "TAB5839", "TAB1828"),
  query = list(
    Region       = "2021",
    Kon          = "*",
    ContentsCode = "*",
    Tid          = "*"
  )
)

Funktionen hämtar då varje tabell separat och lägger ihop resultaten radvis. Om tabellerna inte har exakt samma kolumnstruktur ges en varning. Saknade kolumner fylls då med NA.

5.4 Harmonisering av variabelnamn

Ibland innehåller tabellerna samma typ av information, men SCB har använt olika variabelnamn i olika tabeller. Exempelet nedan är flera tabeller som innehåller samma information, där alla tabeller utom en använder variabelnamnet Region, medan den använder Kommun.

Då kan argumentet harmonise_variable_names användas.

dataset_df2 <- pxweb2_get_data(
  table = c("TAB3266", "TAB3267", "TAB5839", "TAB1828"),
  query = list(
    Region       = "2021",
    Kon          = "*",
    ContentsCode = "*",
    Tid          = "*"
  ),
  harmonise_variable_names = c(Region = "Kommun")
)

Det betyder att variabeln Kommun behandlas som Region.

Harmoniseringen sker i två steg:

  1. Vid hämtningen översätts queryn till rätt variabelnamn för respektive tabell.
  2. Efter hämtningen döps resultatkolumnerna om så att de får samma namn innan tabellerna läggs ihop.

Exempelvis innebär:

harmonise_variable_names = c(Region = "Kommun")

att:

  • användaren kan skriva Region i query
  • tabeller där variabeln heter Kommun hanteras ändå korrekt
  • kolumnen kommun i resultatet döps om till region
  • kolumnen kommun_kod döps om till region_kod

Det gör att de sammanslagna tabellerna får en mer enhetlig struktur.

6 Vanliga urval i query

Argumentet query är en namngiven lista. Namnen motsvarar variabler i tabellen, oftast API-koder som Region, Tid och ContentsCode.

6.1 Hämta alla värden

query = list(
  Region = "*",
  Tid    = "*"
)

6.2 Hämta senaste tidsperiod med 9999

"9999" används som ett användarvänligt alias för senaste tidsvärdet (styrs av latest_period_code, se Hämta den senaste tidsperioden).

query = list(
  Region = "2083",
  Tid    = "9999"
)

Om tabellen har år väljs senaste år. Om tabellen har månader väljs senaste månad. Funktionen använder tidsvariabeln i metadata, inte variabelnamnet i sig.

6.3 Hämta flera värden

query = list(
  Region = c("2081", "2082", "2083"),
  Tid    = c("2023", "2024", "2025")
)

6.4 Wildcard med * och ?

Funktionen kan hantera wildcard-uttryck lokalt mot metadata innan API-anropet skickas (styrs av allow_api_wildcards). Det gör att chunk-logiken fortfarande vet hur många celler uttaget omfattar.

query = list(
  Region = "2083*"
)

Flera wildcard-uttryck kan kombineras:

query = list(
  Region = c("2083A*", "2083B*", "2083C*")
)

? matchar ett enskilt tecken:

query = list(
  Tid = "202?M12"
)

6.5 Klartextvärden i query

Om allow_label_values = TRUE (standard) kan man i många fall ange klartext istället för kod.

dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region = "Hedemora",
    Tid    = "9999"
  ),
  allow_label_values = TRUE
)

Det går också att blanda kod och klartext om metadata tillåter matchningen.

7 DeSO och RegSO

SCB-tabeller kan innehålla flera versioner av DeSO och RegSO, till exempel äldre och nyare indelningar. Paketet har därför stöd för att normalisera och hantera dessa versioner.

7.1 Hämta DeSO, RegSO eller alla geografiska indelningar i en kommun/län

Om du vill hämta alla DeSO eller RegSO i en kommun eller ett län kan du använda wildcard-uttryck som t.ex. 2083* för att få med alla koder som finns i tabellen för Hedemora kommun, alternativt 20* för att hämta alla koder i Dalarnas län. För att hämta alla RegSO, DeSO eller samtliga geografiska indelningar i en kommun:

Region = "2083R*"                                     # hämta alla RegSO i Hedemora kommun
Region = c("2083A*", "2083B*", "2083C*")              # hämta alla DeSO i Hedemora kommun
Region = c("2083A*", "2083B*", "2083C*", "2083R*")    # hämta alla DeSO och RegSO i Hedemora kommun
Region = "2083*"                                      # hämta alla områden som finns i tabellen i Hedemora kommun

Motsvarande för ett län blir följande:

Region = "20??R*"                                     # hämta alla RegSO i Dalarnas län
Region = c("20??A*", "20??B*", "20??C*")              # hämta alla DeSO i Dalarnas län
Region = c("20??A*", "20??B*", "20??C*", "20??R*")    # hämta alla DeSO och RegSO i Dalarnas län
Region = "20*"                                        # hämta alla områden som finns i tabellen i Dalarnas län

7.2 Dela upp kommun och område

Parametern split_deso_regso_by_municipality = TRUE (standard) gör att funktionen försöker skapa kommunuppgifter när regionen är DeSO eller RegSO.

dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region = c("2083A*", "2083B*", "2083C*", "2083R*"),
    Tid    = "9999"
  ),
  split_deso_regso_by_municipality = TRUE
)

Resultatet kan då få extra kolumner:

Kolumn Beskrivning
kommun_kod Fyra första siffrorna i regionkoden
kommun Kommunnamn, när det kan utläsas från labeln
region_kod DeSO-/RegSO-kod utan versionssuffix
region RegSO-namn eller DeSO-kod om DeSO-namn saknas

Om tabellen inte innehåller DeSO eller RegSO ska dessa extra kolumner inte skapas.

7.3 Hantera flera versioner

Parametern deso_regso_versions styr hur versionerade DeSO-/RegSO-koder hanteras.

Tillåtna värden:

Värde Betydelse
"latest" Behåll senaste version med faktiskt värde. Om senaste version har 0 men äldre version har värde över 0, behåll den äldre med värde.
"sum" Ta bort versionssuffix och summera rader som blir dubletter.
NULL Gör ingen versionshantering.

Rekommenderad standard (och default-värde):

deso_regso_versions = "latest"

Exempel:

dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region       = c("2083A*", "2083B*", "2083C*", "2083R*"),
    Hushallstyp  = "*",
    ContentsCode = "*",
    Tid          = "*"
  ),
  deso_regso_versions = "latest",
  split_deso_regso_by_municipality = TRUE
)

7.4 När ska man använda latest respektive sum?

Använd "latest" när DeSO-/RegSO-versioner ska ses som alternativa versioner av samma geografiska område. Det är normalt det säkraste valet.

Använd "sum" när versionerade rader representerar nollrader eller när du uttryckligen vill lägga ihop rader som blir identiska efter att versionssuffixet tagits bort. Denna metod används mycket sällan — normalt är default-värdet "latest" det rimligaste.

Använd NULL om du vill behålla alla versioner separat. I många tabeller är inte detta meningsfullt, då det bara är en version som har värden varje år.

8 Hantering av kod och klartext

Vissa tabeller har labels där kod och klartext ligger tillsammans, till exempel:

"2082 Säter"

Parametern strip_code_in_label = TRUE (standard) gör att funktionen försöker rensa bort kodprefixet när motsvarande kod finns i kodkolumnen.

dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region = "2082",
    Tid    = "9999"
  ),
  strip_code_in_label = TRUE
)

Principen är att bara ta bort koden när klartexten börjar med exakt samma kod. Om labeln bara består av kod, till exempel en DeSO-kod utan namn, behålls koden även som regionnamn.

9 Stora uttag och chunkning

Funktionen delar upp stora uttag i mindre delar när antalet celler blir stort (PxWeb API v2 har ett tak på 150 000 celler per anrop). Detta görs automatiskt, för att undvika att uttag överskrider API-gränser.

Wildcard-uttryck som "2083*" expanderas lokalt mot metadata före chunkning. Det gör att funktionen kan räkna celler utifrån faktiska koder, samtidigt som användaren kan skriva queryn på ett enkelt sätt.

dataset_df <- pxweb2_get_data(
  table = "TAB6568",
  query = list(
    Region       = "2083*",
    Hushallstyp  = "*",
    ContentsCode = "*",
    Tid          = "*"
  )
)
NoteraOvanliga/felaktiga värden i query: on_all_values_invalid

Om samtliga värden du anger för en variabel saknas i tabellen (t.ex. en felstavad region) styr on_all_values_invalid vad som händer: "stop" (standard) avbryter med ett fel, "*" hämtar alla värden för variabeln istället, och "null" gör att hela anropet returnerar NULL. Det sista är praktiskt när du hämtar från flera tabeller där olika år/regioner bara finns i vissa av dem.

10 Skapa query-kod automatiskt

10.1 pxweb2_query_list_template()

Funktionen pxweb2_query_list_template() skapar text för en query-lista utifrån tabellens variabler.

pxweb2_query_list_template("TAB6568")

Exempel med egna standardvärden:

pxweb2_query_list_template(
  table_id  = "TAB6568",
  overrides = list(
    Region = "2083*",
    Tid    = "9999"
  )
)

10.2 pxweb2_data_script_template()

Funktionen pxweb2_data_script_template() skapar ett färdigt kodutkast för att hämta data — skriven till konsolen och (om möjligt) kopierad till urklipp.

pxweb2_data_script_template("TAB6568")

Det kan vara ett snabbt sätt att starta ett nytt skript för en tabell.

11 Rekommenderat arbetsflöde

Ett bra standardflöde är:

  1. Sök fram tabellen med pxweb2_search_tables() eller via SCB:s webbgränssnitt.
  2. Skapa skriptet för att hämta data med pxweb2_data_script_template().
  3. Klistra in med Ctrl + V och få ett skript med ett giltigt pxweb2_get_data()-anrop för den aktuella tabellen.
  4. Kontrollera resultatet: kolumnnamn, regionnivåer, tidsperioder och eventuella DeSO-/RegSO-versioner.

Exempel:

pxweb2_search_tables("helårsekvivalenter")

# Välj en tabell och skapa skriptet för den tabellen
pxweb2_data_script_template("TAB1386")

# Kör Ctrl + V för att få skriptet nedan

dataset_df <- pxweb2_get_data(
  table = "TAB1386",
  query = list(
    Region       = "*",
    Kon          = "*",
    Aldersgrupp  = "*",
    ContentsCode = "*",
    Tid          = "*"
  )
)

12 Hålla ett dataset uppdaterat

Körs ett skript schemalagt (t.ex. nattligt) är det ofta onödigt att hämta om samma data varje gång. pxweb2_table_updated() och pxweb2_table_needs_update() låter dig kontrollera om SCB faktiskt lagt upp en nyare version sedan sist, innan du gör själva datahämtningen:

# Senaste gång tabellen uppdaterades hos SCB
pxweb2_table_updated("TAB6568")
# → "2026-06-02T00:59:31Z"

# Har tabellen uppdaterats sedan ett visst tillfälle?
pxweb2_table_needs_update("TAB6568", reference_datetime = "2025-05-28T06:00:00Z")
# → TRUE/FALSE (NA om tabellens uppdateringstid saknas)

Praktiskt i ett schemalagt skript: spara tidpunkten för senaste lyckade hämtning, och skippa pxweb2_get_data()-anropet (och allt som bygger på det) om pxweb2_table_needs_update() ger FALSE.

13 Andra PxWeb-instanser

Alla funktioner tar ett base_url-argument, med SCB:s statistikdatabas som standard. Tabell-id:n valideras inte mot SCB:s namngivning — finns inte ett id på den angivna base_url, kastar pxweb2_get_metadata() ett tydligt fel (HTTP 404) istället för att gissa.

pxweb2_get_data(
  table    = "NågotTabellId",
  query    = list(...),
  base_url = "https://en-annan-pxweb-instans.se/api/v2/tables/"
)
TipsRelaterat paket: pxweb

pxweb (rOpenGov) är det etablerade, generella R-biblioteket för PxWeb-API:er och stödjer både v1 och v2. pxweb2r är ett smalare, mer opinionerat paket byggt specifikt mot v2-API:et (t.ex. att slå ihop flera tabeller, DeSO-/RegSO-hantering och arbetsflödeshjälparna ovan) — värt att prova pxweb också om du behöver bredare PxWeb-instansstöd eller v1.

14 Vanliga problem och lösningar

14.1 Fel: unused argument

Om du får ett fel som:

unused argument (...)

kontrollera att argumentnamnet i funktionsanropet matchar funktionsdefinitionen — pxweb2r:s parametrar heter på engelska (t.ex. harmonise_variable_names).

14.2 Tomma kommun-kolumner i tabeller utan DeSO/RegSO

Splitfunktionen ska bara lägga till kommun_kod och kommun när tabellen faktiskt innehåller DeSO eller RegSO.

14.3 Kod och klartext ligger i samma kolumn

Vissa tabeller kan ha labels som innehåller både kod och namn. Använd:

strip_code_in_label = TRUE

Då försöker funktionen rensa bort kodprefixet på ett kontrollerat sätt.

16 Sammanfattning

  • Använd pxweb2_get_data() för själva datahämtningen.
  • Använd pxweb2_search_tables() för att hitta tabeller i databasen.
  • Använd pxweb2_data_script_template() för att snabbt skapa ett skriptutkast för datahämtning.
  • Använd pxweb2_get_metadata(), pxweb2_get_variables() och pxweb2_get_values() för att förstå tabellens struktur, och pxweb2_get_codelist()/pxweb2_list_codelists() för kodlistor/aggregeringar.
  • Använd pxweb2_table_updated()/pxweb2_table_needs_update() för att undvika onödiga omhämtningar i schemalagda skript.
  • Använd "9999" för senaste tidsperiod.
  • Använd * och ? för wildcard-urval.
  • Använd deso_regso_versions = "latest" som standard för DeSO/RegSO.
  • Använd split_deso_regso_by_municipality = TRUE för att skapa kommun_kod och kommun när tabellen innehåller DeSO/RegSO.
